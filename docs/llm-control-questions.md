# Контрольные вопросы: проверка параметров генерации LLM

> **TL;DR**: 10 коротких вопросов, по которым видно, как `temperature`, `top_p` и `top_k`
> меняют ответы DeepSeek и локальной Ollama. Панель настроек — вкладка «Чат» → правая колонка →
> блок **«Генерация LLM»**. Автопрогон — `scripts/run_sampling_checks.py` (результаты в
> `docs/scenarios/sampling-check.{md,json}`).

Машиночитаемая версия для скрипта: [`scripts/sampling_questions.json`](../scripts/sampling_questions.json).

## Что и как проверять

Панель **«Генерация LLM»** в правой колонке чата:

- **Temperature** (0…2) — 0 = детерминированно (один и тот же ответ), выше = разнообразнее.
- **Top_P** (0…1) — нуклеус-сэмплинг. `1.0` — без ограничения; маленькое значение (0.1) сужает
  выборку до самых вероятных токенов → ответы становятся стабильнее.
- **Top_K** (0…200) — **только Ollama** (DeepSeek API не поддерживает `top_k`). `1` = жадно по
  одному лучшему токену → ответы детерминированны даже при высокой температуре.
- **Отключить размышления (Ollama)** — `think:false` в нативном API, экономит токены.

### Ожидаемые эффекты

| Сценарий | Настройки | Что ожидать |
| --- | --- | --- |
| Детерминизм | temperature = 0 | Повторы максимально **похожи** (у обоих провайдеров). Точного совпадения байт-в-байт может не быть: DeepSeek — MoE-модель (серверный недетерминизм), у локальной Ollama — недетерминизм float при длинном промпте. |
| Креатив | temperature = 1.5 | Ответы между повторами **сильно различаются** (все вопросы 1–10). |
| Контроль Top_K (Ollama) | temperature = 1.5, **top_k = 1** | Похожесть повторов возвращается к уровню temperature=0 — top_k реально применяется. |
| Контроль Top_P (DeepSeek) | temperature = 1.5, **top_p = 0.01** | Похожесть повторов заметно **выше**, чем при top_p=0.95 — top_p реально применяется (эффект слабее, чем у top_k: сказывается недетерминизм DeepSeek). |
| Экономия токенов (Ollama) | Отключить размышления | Размышлений нет, ответ короче и быстрее (см. `eval_count` в отчёте). |

> **Важно**: абсолютная детерминированность LLM не гарантируется (даже при temperature=0). Поэтому в
> автопрогоне сравнивается **средняя похожесть** повторов (`difflib`), а не строгое равенство. Ключевой
> сигнал — конфигурация B (temperature=1.5) даёт заметно меньшую похожесть, чем A (temperature=0) и C
> (контроль top_p/top_k).

### Как проверить вручную

1. Вкладка «Чат», выберите провайдера в дропдауне (DeepSeek / Ollama).
2. В панели справа выставьте `Temperature = 0`, задайте один из вопросов **дважды**
   (например, в новом чате — «+ Новый чат») → ответы должны совпасть.
3. Выставьте `Temperature = 1.5`, повторите → ответы должны отличаться.
4. Для Ollama выставьте `Top_K = 1` при `Temperature = 1.5` → ответы снова совпадут.
5. Для DeepSeek выставьте `Top_P = 0.01` при `Temperature = 1.5` → ответы стабилизируются
   (похожесть выше, чем при `Top_P = 0.95`).
6. Смотрите блок **LOG** (вкладка LOG): там видны `temperature`/`top_p`/`top_k` в контексте запроса
   и `reasoning`/`content` в ответе.

## Автопрогон

```powershell
# из корня проекта (скрипт сам поднимет/остановит сервер)
.\.venv\Scripts\python.exe scripts\run_sampling_checks.py
```

Скрипт прогоняет вопросы по обоим доступным провайдерам в конфигурациях A/B/C, считает долю
совпадающих повторов и сохраняет отчёт в `docs/scenarios/sampling-check.md` и `.json`.
Требуется запущенная Ollama с моделью (`ollama pull qwen3:1.7b`) и `DEEPSEEK_API_KEY` в `.env`
(если провайдер недоступен — блок пропускается).

## Рекомендованная конфигурация для локальной модели (qwen3:1.7b)

| Параметр | Значение | Почему |
| --- | --- | --- |
| Temperature | **0.7** | Баланс стабильности и живости для чата. |
| Top_P | **0.8** | Чуть сужает выборку, ответы менее «рваные», чем при 1.0. |
| Top_K | **20** | Дефолт qwen3: отсекает маловероятный «мусор», стабилизирует. |
| max_tokens (num_predict) | **1000** | Хватает для ответа; вместо 2000 → меньше токенов на «болтовню». |
| Отключить размышления | **вкл**, если размышления не нужны | Самая большая экономия: thinking у qwen3 съедает больше токенов, чем сам ответ. |

Итого для обычного чата: `temperature=0.7`, `top_p=0.8`, `top_k=20`, размышления выключены.
Для «творческих» задач — `temperature=1.0–1.3`, размышления можно включить.
Для фактических/структурных — `temperature=0.2–0.4`, `top_k=10`.
